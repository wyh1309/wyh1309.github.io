From Virtual Memory to PagedAttention: How Block Tables Map KV Cache

TL;DR#

PagedAttention is virtual memory for the KV cache. The same idea an OS uses to map virtual pages onto physical frames — a page table — becomes vLLM’s block table that maps logical KV-cache blocks onto physical GPU-memory blocks. Once you see that analogy, PagedAttention and Continuous Batching stop being magic.

Why KV-cache memory is a problem#

During decoding, every generated token attends to all past tokens, so the attention cache grows linearly with sequence length. With naive preallocation you either over-allocate (wasting memory on idle capacity) or fragment it when requests have different lengths. Serving many requests at once makes the waste dominate.

The OS lesson: paging#

Virtual memory splits address space into fixed-size pages, and a page table maps each virtual page to a physical frame. The OS only loads pages that are actually used, so a large logical address space fits in much less physical memory — and fragmentation is handled by the mapping layer, not by the application.

PagedAttention: block table = page table#

vLLM reuses this exact design:

logical KV blocks  --block table-->  physical GPU memory blocks

flowchart LR
    L[Logical blocks (per sequence)] --> BT[Block Table]
    BT --> P1[(Physical block 0)]
    BT --> P2[(Physical block 1)]
    BT --> P3[(Physical block N)]
  • The KV cache is split into fixed-size blocks (e.g. 16 tokens each).
  • Each sequence owns a block table mapping its logical blocks to physical blocks in GPU memory.
  • Blocks are allocated on demand, so memory is used only for tokens that exist, and non-contiguous physical blocks are fine — the table resolves the mapping.

The result: near-zero fragmentation and the ability to share blocks (used by parallel sampling, where multiple sequences share a prefix).

Takeaway#

OS concept PagedAttention
virtual page logical KV block
physical frame physical GPU block
page table block table
demand paging on-demand block allocation

LLM inference systems are systems-engineering problems. Knowing your OS pays off directly when reading vLLM source.
