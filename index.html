From Virtual Memory to PagedAttention: How Block Tables Map KV Cache

A 7B model burns ~512 KB of HBM per generated token. On an A100 with 40 GB, that's 80k tokens total — yet serving a batch of 100 concurrent requests wastes more than half of it. The culprit isn't the math; it's how the KV cache is laid out. This post walks through why contiguous KV-cache allocation causes fragmentation, how OS paging solves the same problem, and how vLLM's block table is literally a page table for GPU memory.
